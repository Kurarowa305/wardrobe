# Domain Docs

## レイアウト

single-context: apps/api と apps/web でドメイン資料を共有します。

- 用語集: ルートの `GLOSSARY.md`
- 設計判断: `docs/adr/`

## コード調査前に読む資料

- `GLOSSARY.md`
- 調査対象に関係する `docs/adr/` の ADR
- AGENTS.md の指示に従い、関連する `design/` の設計資料と
  `design/タスク設計/` のタスク説明

用語集や ADR がまだ存在しない場合は、そのまま調査を進めてください。
不在を指摘したり、事前作成を提案したりする必要はありません。
domain-modeling スキルで用語や設計判断が確定した時に作成します。

## 用語と設計判断の扱い

Issue、提案、仮説、テスト名では用語集に定義された語を使用してください。
必要な概念が未定義なら、既存の語で表現できるか確認し、
実際の不足は domain-modeling の対象として記録してください。

既存 ADR と矛盾する提案では、対象 ADR と見直し理由を明示してください。
