# ホーム改修の結合仕上げ（#284）

## 前提と範囲

[Issue #284](https://github.com/Kurarowa305/wardrobe/issues/284)のBlocked by #281/#283解消後、#279〜#283の統合成果を検証する。仕様は#272および#274〜#277/#288の確定判断を維持する。新しいUI案や季節判定の再設計は行わない。

## 接続する境界

```text
Web endpoint/client → local HTTP router → 各domain handler → DynamoDB Local
                                      → Open-Meteo固定fixture
HomeTabScreen → useHome / useConfirmation → endpoint / QueryClient
既存画面 / PWA起動判定 → DOM操作 / fixture
```

API検証は実テーブルにTerraformと同じ5GSIを用意し、公開APIで作成・記録・削除する。共有天気以外のランキング/統計/再送処理をテスト専用実装へ差し替えない。Web検証は実component/hookを描画し、利用者のクリック・入力・focus・結果を確認する。既存の契約/並行更新/期限テストも継続する。

## 成果物と完了条件

- 実HTTP＋DBとWeb操作の結合スクリプトをCIへ登録し、資格情報や実予報なしで実行する。
- [テスト設計](../テスト設計/ホーム改修_結合検証284.md)で全受入項目と実行テストを対応付ける。
- API/DB/画面/TanStack Query資料の「後続で接続予定」を現在の責務と動作へ更新する。
- 環境/デプロイ資料に現在の設定、出典、監視イベント、API→Webの反映順、履歴操作記録を守る復旧条件を明記する。
- 対象SHAの独立Standards/SpecレビューとGitHub Actions CI成功を確認して通常マージする。既存Vercel Previewの失敗はGitHub Actions CIとは別に記録する。

既存のmaster pushによるdev反映は運用を維持する。新規本番環境・有料契約・実予報精度の調査はこの結合検証に含めない。

## 結合検証で修正したPWA起動

React StrictModeがeffectをsetup→cleanup→setupする場合、従来の`hasResolvedRef`は最初の非同期結果をcleanupで無効化したまま次のsetupも遮断し、保存済みワードローブからの起動が空画面になる。重複setupをrefで遮断せず、effectごとのactive状態で古い結果だけを無効化する。再現テストは修正前の失敗を確認し、通常起動・StrictModeの両方で画面遷移を検証する。
