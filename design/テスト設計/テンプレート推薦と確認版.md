# テンプレート推薦・確認版 #281

公開境界は推薦handlerとテンプレートusecase、SDKとDynamoDB間のHTTP。`pnpm --filter api test:template-recommendations` と `test:template-revision` をCIに追加。Node20で実行する。

## 推薦

- 手動は地域未設定でも天気解決を呼ばず、テンプレート自身の季節タグで絞る。autoは地域なし/天気なし/空/readyを区別。15/25度境界、体感優先、実気温fallback、自動春OR秋とallを検証。
- 全ページを読み、後続ページの最良候補、構成服max(lastWornAt)順、createdAt→IDの同点順、未着用0、共通服を含む候補の維持、削除/真の欠落の除外を確認。
- 未処理キー・throttleで部分成功や再送をしない。未知/重複query、mode、省略auto、実在ISO日、厳密整数、地域revision、入口/応答時JST跨日を確認。
- 実タイマーでDB5秒と入口10秒残時間の短縮を実行し、待機中signalのabortと後続読取未開始を確認。
- 実AWS SDK→ローカルDynamoDB protocol HTTP serverでQuery/BatchGet/Getを受信。ベースPK、ConsistentRead、80件、並行最大4、SDK throttle要求が1回であることを検証。実DynamoDBデータサービスの統合テストとは区別する。

## 測定

ローカル模擬HTTP、Node20、BatchGet各10ms遅延。総テンプレート1,000（削除500）、ユニーク服500で、Query5ページ、BatchGet7、並行最大4、META2取得、所要約74ms。RCUと実AWS latencyは未測定。GSIを使わず全削除行もQuery読取へ含まれることを確認する。候補数に比例する読取を許容する設計であり、実AWSの速度保証ではない。

## 確認版

新規1、既存欠損0、内容編集+1、同内容編集維持、削除+1、同時編集/削除の片方409、更新/削除のDynamoDB ACTIVE・旧revision条件、統計を上書きしないことを検証。既存統計回帰も実行する。

TDD: handler未実装→手動green、auto未実装のempty→region_required/OR green、detail revision未実装undefined→1および編集/削除greenを確認。
