# 確認記録と再送 #283

公開seam: 履歴POST/DELETE handler、ConfirmationController、確認ダイアログ。APIの実transactionをDynamoDB Local 1.25.1へ送る。dynaliteのtransaction未対応をモックで成功扱いにしない。

- `pnpm --filter api test:confirm-record`: 確認版と実在日。
- `bash scripts/run-confirm-record-dynamodb-tests.sh`: 20服44項目、201/200・同キー内容違い409、削除後再送409、同日別操作、統計によるrevision不変、テンプレート編集後の成功再送、read後の版競合、削除服、旧body・未来日。書込成功応答喪失と同キー並行送信も検証する。
- `pnpm --filter web test:confirm-record`: JST初期日、日付維持、未確定localStorage保存/復元、同body/key再送、storage失敗時送信なし、連打・キャンセル・stale再確認。HTTP/MSWで同じ服を共有する別テンプレートの順位変更・削除後復帰も確認。DOMで可視見出しなし/読み上げ名、20服+16、背景/Escape/送信中抑止、起点消失後のフォーカスを検証する。

CIはJava17と固定SHA256の公式DynamoDB Local配布を使用する。資格情報はローカル用のダミー、テーブルは実行毎に一意、finallyで削除する。外部AWSへテストデータを保存しない。手元にサーバーがある場合は `DDB_ENDPOINT=http://127.0.0.1:8765 bash scripts/run-confirm-record-dynamodb-tests.sh`。自動起動したプロセスは終了時に停止する。

開発中のred: confirmed input未対応、再送が201になり二重記録する旧挙動、未実装controller。green: 実DynamoDB/公開操作経由で再送保証と統計の一回だけ更新を確認。既存統計整合テストも回帰実行する。

レビュー回帰: 最初の操作読取が未確定で、その後に他要求が成功し確認版が変わった場合も、事前検証の失敗より成功操作の200（削除済みなら墓標409）を優先する。公開handlerで最初の読取結果だけを固定し、後続の操作照合は実DynamoDBに接続する。複数controllerを保存前に作成して同時送信し、2操作が残ること・片方の確定で他方が消えないこと・各操作を復元再送できることを検証する。修正前はstale409と保存件数1で失敗、修正後に成功。
