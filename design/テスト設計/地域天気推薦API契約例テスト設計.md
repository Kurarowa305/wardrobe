# 地域と天気とテンプレート推薦のAPI契約例のテスト設計

対象は[#276の確定契約](../タスク設計/地域天気テンプレート推薦_API契約と状態管理判断.md)に記載したJSON例と関連設計からの参照。API機能・共有キャッシュ・記録transactionの実装テストではなく、実装担当が利用する例の破損と矛盾を検出する。

実行: `node scripts/check-api-contract-276-examples.mjs`。Node標準ライブラリのみを使用し、CIの独立stepで実行する。外部通信は行わない。

| ケース | 期待結果 |
| --- | --- |
| JSON例の解析と種類 | 検索・天気・手動推薦・地域未設定・候補0件・確認競合の6例を解析可能 |
| 地域検索例 | ABR6桁識別子、表示名、辞書版、最大10件とhasMoreが契約に従う |
| 天気例 | Open-Meteo Best Match、JST、°C、取得日時、翌00:00失効、気象値と独自指数の整合 |
| 推薦例 | mode・basis・状態・最大3件・全構成服・確認版が契約に従い、内部季節を含まない |
| 不正例の拒否 | 4件、空のready、手動で地域要求、負の確認版、削除服、内部季節を拒否 |
| エラーと参照 | 既存CONFLICT形式とCONFIRMATION_STALE、API・DB・TanStackQuery設計からのリンクが有効 |

本テストを#279〜#284の振る舞い検証の代用にしない。日付・地域競合、未処理キー・期限、二重送信、履歴削除後再送、localStorage復元、lease・counterの原子性と上限、全経路無効化は各機能実装と結合検証で確認する。
