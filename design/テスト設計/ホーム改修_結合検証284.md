# ホーム改修の結合検証（#284）

## 方針・実行環境

Node.js 20、pnpm 10.27.0、`pnpm install --frozen-lockfile`を使用する。DBテストは一意の一時テーブルと5GSIを作成し、終了時に削除する。DynamoDB Local以外のエンドポイントを拒否し、ダミー認証のみを使用する。

```bash
# Java 17以上。DDB_ENDPOINT未指定ならSHA検証したDynamoDB Localを起動・終了
pnpm --filter api test:home-integration
pnpm --filter api test:confirm-record-dynamodb
pnpm --filter web test:home-record-integration
pnpm --filter web test:legacy-web-integration
```

既に起動したDBには`DDB_ENDPOINT=http://127.0.0.1:8765`を渡せる。runnerの任意コマンド対応を共用し、Java telemetryを無効化する。Open-Meteoのfetchだけ固定fixtureに置き換え、Web→local HTTPおよびSDK→DynamoDBは実通信を行う。fixture以外の外部接続を検出したら失敗させる。依存とDB配布物の初回ダウンロードは必要だが、実予報・AWS/S3資格情報は不要。

## CI・結果の記録

`.github/workflows/ci.yml`に各scriptを明示登録する。既存のAPI/Webテスト、型検査、production build、辞書/契約検査を維持する。CIには実サービス用のsecretを渡さない。

実行結果と最終対象SHA、レビュー指摘・修正は#284と関連PRに残す。fixtureは日次契約・取得制御・状態遷移の証拠であり、地域別の実予報精度、実AWS負荷性能、実端末での配信後確認の完了を意味しない。配信後の手順は[デプロイ手順](../デプロイ手順.md)を参照する。
