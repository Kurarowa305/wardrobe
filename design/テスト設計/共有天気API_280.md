# 共有天気API #280 テスト

公開 seam は天気HTTP handlerと、推薦から共用するweather service。外部予報は固定fixture、DynamoDBはdynaliteへ実AWS SDK commandを送り、条件式・予約競合・所有者条件を実行する。実APIに接続するテストはCIへ入れない。

`pnpm --filter api test:weather` を `.github/workflows/ci.yml` に追加。開発中は地域未設定→天気available、入力厳格化、DynamoDB条件式をred→greenで確認した。最初の共有実行ではTTL予約語を検出し、式属性名へ修正した。

- 指数: -8/14.999/15/24.999/25/38°C、体感13・実気温18、最低5・最高26、丸め前境界。
- 欠損: null/文字列/Infinity・個別単位不一致、未知WMO、配列不整合、別日。最高実気温fallbackの指数はnull。
- 入力: 実在日、必須query、重複query、未知属性、負数/小数/安全整数外、pathのwardrobeIdをqueryで上書きできないこと。
- 共有: 別service要求のキャッシュ利用、6同時要求で外部1回、lease期限切れのowner拒否、provider gateを短縮できないこと、古い予約CAS失敗。
- 障害: network失敗は再試行せず5分抑止、429/Retry-Afterは別地域も抑止、有効な当日キャッシュはprovider障害中も利用。
- 予算: 80%警告、100%停止、秒/分/時/日バケットとUTC月境界、古い境界バケットの保守的合算。
- 期限: DB読取合計5秒、入口10秒、実fetch4秒でAbortSignal中断、予約書込が秒境界を跨いだ後の送信抑止、JST跨日・応答中地域変更拒否。

dynaliteは実AWSのIAM/TTL削除タイミングを模擬しない。IAM・ルーティング・TTL設定は既存Terraformチェックと追加設定のレビューで確認し、物理TTL削除を成功条件にしない。予報精度は検証していない。実接続の既存証拠は[調査記録](../タスク設計/Open-Meteo_実接続と運用条件判断.md)を参照。
